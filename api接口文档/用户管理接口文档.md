## 1. 接口概述

本文档描述了用户管理系统的RESTful API接口，包括用户的查询、创建等基础功能。

### 1.1 技术栈
- **后端框架**: Spring Boot 3.x
- **数据库**: MySQL 8.0
- **ORM框架**: MyBatis-Plus
- **JSON处理**: Jackson

### 1.2 接口特性
- 统一JSON格式请求和响应
- 统一错误处理机制
- 请求日志记录
- 参数验证

## 2. 通用说明

### 2.1 请求格式
- **Content-Type**: `application/json`
- **字符编码**: `UTF-8`
- **请求方法**: 仅支持 GET 和 POST
- **参数传输**: 统一使用JSON格式在请求体中传输

### 2.2 响应格式
所有接口统一返回以下格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": "2025-09-19T13:30:00Z"
}
```

### 2.3 状态码说明
| 状态码 | 含义 | 说明 |
|--------|------|------|
| 200 | 成功 | 请求处理成功 |
| 201 | 创建成功 | 资源创建成功 |
| 400 | 请求错误 | 参数格式错误或缺失 |
| 401 | 未授权 | 未登录或token无效 |
| 403 | 禁止访问 | 无权限访问 |
| 404 | 资源不存在 | 请求的资源不存在 |
| 409 | 资源冲突 | 资源已存在 |
| 423 | 账户锁定 | 账户被锁定 |
| 500 | 服务器错误 | 系统内部错误 |

## 3. 用户管理接口

### 3.1 获取用户列表

#### 基本信息
- **接口标识**: `USER_LIST`
- **请求路径**: `POST /api/users/list`
- **接口描述**: 获取系统中所有用户列表
- **认证要求**: 无需认证

#### 请求参数
```json
{}
```
*注：当前版本无需传递参数，传递空JSON对象即可*

#### 请求示例
```bash
curl -X POST http://localhost:8080/api/users/list \
  -H "Content-Type: application/json" \
  -d '{}'
```

#### 响应示例
```json
{
  "code": 200,
  "message": "获取用户列表成功",
  "data": [
    {
      "id": 1,
      "username": "testuser"
    },
    {
      "id": 2,
      "username": "admin"
    }
  ],
  "timestamp": "2025-09-19T13:30:00Z"
}
```

#### 异常响应
```json
{
  "code": 500,
  "message": "系统繁忙，请稍后重试",
  "data": null,
  "timestamp": "2025-09-19T13:30:00Z"
}
```

### 3.2 根据ID获取用户

#### 基本信息
- **接口标识**: `USER_GET_BY_ID`
- **请求路径**: `POST /api/users/getById`
- **接口描述**: 根据用户ID获取用户详细信息
- **认证要求**: 无需认证

#### 请求参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | Long | 是 | 用户ID |

#### 请求示例
```bash
curl -X POST http://localhost:8080/api/users/getById \
  -H "Content-Type: application/json" \
  -d '{
    "userId": 1
  }'
```

#### 成功响应
```json
{
  "code": 200,
  "message": "获取用户成功",
  "data": {
    "id": 1,
    "username": "testuser"
  },
  "timestamp": "2025-09-19T13:30:00Z"
}
```

#### 异常响应
```json
{
  "code": 404,
  "message": "用户不存在",
  "data": null,
  "timestamp": "2025-09-19T13:30:00Z"
}
```

### 3.3 创建用户

#### 基本信息
- **接口标识**: `USER_CREATE`
- **请求路径**: `POST /api/users`
- **接口描述**: 创建新用户
- **认证要求**: 无需认证

#### 请求参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| username | String | 是 | 用户名 |

#### 请求示例
```bash
curl -X POST http://localhost:8080/api/users \
  -H "Content-Type: application/json" \
  -d '{
    "username": "newuser"
  }'
```

#### 成功响应
```json
{
  "code": 200,
  "message": "创建用户成功",
  "data": {
    "id": 3,
    "username": "newuser"
  },
  "timestamp": "2025-09-19T13:30:00Z"
}
```

#### 异常响应
```json
{
  "code": 400,
  "message": "用户名不能为空",
  "data": null,
  "timestamp": "2025-09-19T13:30:00Z"
}
```

## 4. 数据模型

### 4.1 UserEntity (用户实体)
```json
{
  "id": "Long, 用户ID，主键",
  "username": "String, 用户名，唯一标识"
}
```

### 4.2 UserIdRequest (用户ID请求)
```json
{
  "userId": "Long, 用户ID"
}
```

### 4.3 ApiResponse (统一响应格式)
```json
{
  "code": "Integer, 业务状态码",
  "message": "String, 响应描述信息",
  "data": "Object, 响应数据，可为null",
  "timestamp": "String, 服务器响应时间戳，ISO 8601格式"
}
```

## 5. 错误码说明

### 5.1 业务错误码
| 错误码 | 错误信息 | 说明 | 解决方案 |
|--------|----------|------|----------|
| 400 | 参数验证失败 | 请求参数格式错误或缺失必填参数 | 检查请求参数格式和必填字段 |
| 404 | 用户不存在 | 指定的用户ID不存在 | 确认用户ID是否正确 |
| 500 | 系统繁忙，请稍后重试 | 服务器内部错误 | 联系系统管理员 |

### 5.2 系统错误码
| 错误码 | 错误信息 | 说明 |
|--------|----------|------|
| 500 | 数据库连接失败 | 数据库服务不可用 |
| 500 | JSON解析错误 | 请求体JSON格式错误 |
