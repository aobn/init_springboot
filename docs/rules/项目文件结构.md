## 目录重命名建议

### 1. 文档目录标准化
```bash
# 将 api接口文档 重命名为 docs/api
mv "api接口文档" docs
mkdir -p docs/api docs/design docs/deployment
mv docs/* docs/api/
```

### 2. 规则文档整合
```bash
# 将 rule 目录整合到 docs 中
mv rule docs/rules
```

### 3. 创建缺失的标准目录
```bash
# 创建脚本目录
mkdir -p scripts/sql scripts/deploy scripts/tools

# 创建测试目录结构
mkdir -p src/test/java/com/example/demo/{controller,service,integration}
mkdir -p src/test/resources/test-data

# 创建Java包结构
mkdir -p src/main/java/com/example/demo/{config,controller,service,repository,entity,dto/{request,response},common/{constants,enums},security,utils}

# 创建资源目录
mkdir -p src/main/resources/{static,templates,db/migration}
```

## 包结构说明

### 1. 分层架构
- **controller**: 控制器层，处理HTTP请求
- **service**: 业务逻辑层，处理业务规则
- **repository**: 数据访问层，与数据库交互
- **entity**: 实体类，对应数据库表
- **dto**: 数据传输对象，用于API交互

### 2. 公共模块
- **common**: 公共类和工具
- **config**: 配置类
- **security**: 安全相关类
- **utils**: 工具类

### 3. 测试结构
- **controller**: 控制器单元测试
- **service**: 服务层单元测试
- **integration**: 集成测试

## 配置文件建议

### 1. 多环境配置
- `application.yml`: 主配置
- `application-dev.yml`: 开发环境
- `application-prod.yml`: 生产环境
- `application-test.yml`: 测试环境

### 2. 数据库迁移
使用Flyway或Liquibase管理数据库版本

### 3. Docker支持
添加Dockerfile和docker-compose.yml支持容器化部署

## 实施步骤

1. **备份当前项目**
2. **执行目录重命名和创建**
3. **移动现有文件到对应目录**
4. **创建标准配置文件**
5. **更新Maven配置**
6. **添加必要的依赖**
7. **创建基础的测试类**

## 注意事项

1. **渐进式重构**: 不要一次性改动太多，分步骤进行
2. **保持向后兼容**: 确保现有功能不受影响
3. **更新文档**: 及时更新相关文档
4. **团队沟通**: 与团队成员同步结构变更

这个标准化结构将使项目更易维护、扩展和团队协作。
